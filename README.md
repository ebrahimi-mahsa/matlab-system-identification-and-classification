# System Identification and Classification in MATLAB

A MATLAB project exploring how measured data can be used to identify a dynamic system and build a classifier. The work combines recursive parameter estimation, model order selection, residual analysis, and feature-based classification in a single Live Script that presents the code alongside the engineering reasoning and visual results.

Developed as part of my master's studies in Automation Engineering.

## Project background

I originally developed this code for an academic examination using datasets supplied by course-specific MATLAB functions. Access to those functions was time restricted, so I can no longer use them to generate the original datasets.

## Project overview

The project addresses two complementary tasks:

- **System identification:** estimate an AR or ARX model from input–output measurements, compare candidate model orders, and assess the residuals.
- **Classification:** construct quadratic features and train a linear support vector machine to distinguish two classes with a nonlinear boundary in the original feature space.

The main report is [`Identification_Classification_Demo.mlx`](Identification_Classification_Demo.mlx). Run and save the Live Script to explore each stage with its plots and numerical outputs.

## 1. System identification

The identification workflow uses 2,000 input–output samples and proceeds through four stages.

### Model structure assessment

The code checks whether the input varies and examines input–output cross-correlation to suggest an AR or ARX structure. This is a practical screening heuristic; correlation alone does not establish causality or uniquely determine the correct model structure.

### Recursive least squares estimation

A custom recursive least squares implementation updates the parameter estimates one sample at a time. A convergence plot shows how the estimates evolve as measurements become available.

For an ARX model of order n, the regressor includes past output and input samples:

```text
phi(t) = [-y(t-1), ..., -y(t-n), u(t-1), ..., u(t-n)]
```

The prediction is formed from this regressor and the estimated parameter vector.

### Model order selection

Candidate orders from 1 to 10 are compared using:

- Final Prediction Error (FPE).
- Akaike Information Criterion (AIC).
- Minimum Description Length (MDL).

The final order is selected by minimizing MDL. The criteria illustrate the tradeoff between fitting the measurements and increasing model complexity.

### Residual diagnostics

After estimating the selected model, the code examines residual variance, residual autocorrelation, and—for an ARX model—residual–input cross-correlation. Correlation plots and approximate statistical tests help identify unexplained temporal structure or remaining input dependence.

These checks use the identification record itself. They provide in-sample diagnostics rather than an independent assessment on a separate validation dataset.

## 2. Classification

The classification workflow uses two input features, 1,000 training samples, and 600 separate test samples.

The training-set mean is used to center both training and test data. Each sample is then mapped to five features:

```text
[x1, x2, x1^2, x1*x2, x2^2]
```

A linear support vector machine is trained in this expanded feature space. The quadratic terms allow it to represent a nonlinear decision boundary in the original two-dimensional space.

The analysis reports training and test classification error and visualizes the test samples, learned decision boundary, and misclassified points. Centering uses the training set only; test labels are used for evaluation, not fitting.

## Demonstration datasets

The public version uses reproducible synthetic datasets generated by [`generate_demo_data.m`](generate_demo_data.m), with random seed 42. No external data download or course-specific generator is required.

**Identification data** come from a stable second-order ARX system:

```text
y(t) = 0.7*y(t-1) - 0.2*y(t-2)
     + 0.8*u(t-1) + 0.3*u(t-2) + e(t)
```

The input is Gaussian white noise and the innovation standard deviation is 0.2. A 300-sample burn-in is discarded before retaining the 2,000 samples used in the analysis. The known coefficients provide a reference for interpreting parameter estimates.

**Classification data** contain uniformly distributed two-dimensional samples with a circular class boundary and noise added to the labeling score. Training and test samples are generated separately.

These datasets provide a controlled example for exploring the analysis methods; performance on real-world measurements would require separate evaluation.

## Getting started

### Requirements

- MATLAB with Live Editor support.
- Statistics and Machine Learning Toolbox for SVM training and classification plots.
- Availability of `xcorr`; older MATLAB releases may require Signal Processing Toolbox.

### Run the project

1. Download or clone the repository.
2. Set the project folder as the MATLAB **Current Folder**.
3. Open `Identification_Classification_Demo.mlx`.
4. Click **Run** to execute the complete workflow.
5. Save the Live Script to retain the generated plots and outputs.

Keep the Live Script, dataset generator, and `Functions` directory together. Run the full workflow before running later sections individually, since they depend on variables created earlier.

## Outputs

Running the Live Script produces:

- An input–output scatter plot.
- Parameter convergence curves.
- A comparison of normalized model selection criteria.
- Estimated model parameters and residual statistics.
- Residual autocorrelation and residual–input correlation plots.
- Training data visualization.
- Training and test classification errors.
- A test-set plot showing the decision boundary and misclassified samples.

The numerical results are calculated during execution rather than fixed in this README.

## Engineering focus

This project connects estimation and classification theory with explicit MATLAB implementations. Its main focus is understanding how parameter estimates evolve, how model complexity affects selection, how residuals reveal model limitations, and how feature design changes the boundary a classifier can learn.
